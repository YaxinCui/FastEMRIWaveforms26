# 六链路接口：把可复用计算接起来，而不改变物理算子

## 这一次解决什么

FEW 输出源的引力波；探测器响应先把它投影成六条链路的相对频率变化，
再对链路数据做时间延迟组合，形成 XYZ / AET / AE。两步可分开处理，
因此链路数组入口是缓存、跨模块组合和独立验算的重要连接点。
这一分解对应 [Katz 等，2022，§IV.2–IV.3](https://arxiv.org/html/2204.06633)。

本机 fastlisaresponse 1.1.17 的 `get_tdi_delays(y_gw=...)` 却引用了不存在的
`link_space_craft_0_in`；全新对象还缺少裁剪位置和内部链路状态。
不是调用者的物理参数错了，而是公共入口的状态约定不完整。
证据见 [原版复现](../collaboration/linux/original_failure.json) 与
[原版源码](../collaboration/linux/original/response.py)。

本实验只替换局部副本中这一方法：

```python
# 1.1.17 语义：t0 是两端缓冲秒数，不是绝对时间起点。
xyz = response.get_tdi_delays(full_six_links, t0=20000.0)
```

`full_six_links` 必须是 `(6,N)` 的普通 NumPy FP64 数组，包含完整缓冲区。
按实际轨道对象的 `[12,23,31,13,32,21]` 排列；编号前者为接收、后者为发射。
允许非连续、只读数据，内部进行独立复制；不自动猜顺序、转换复数或降精度。
输入、时间、拓扑、插值缓冲不合法时先报错；native 和通道转换成功且结果有限后
才提交新状态。XYZ 保留当前输出的 view 约定，后次调用不会覆盖旧返回值。

## 为什么检查缓冲区不能只看数组长度

设插值参数为 `order`，令 `h=(order+1)//2`。原生函数实际先计算
`d=ceil(delay*fs)-1`，随后无条件读取下标 `d-h+1` 到 `d+h`。
25 阶会读取完整 26 个样本，即使个别权重恰为零也不能读出数组边界。
所以必须满足 `h-1 <= d <= N-1-h`。

实验采用保守门限 `cut >= ceil(Kmax*Lmax*fs)+h+2`，其中 `Kmax` 是单个
组合的有效延迟次数，`Lmax` 来自实际配置的光行时数组；另检查轨道插值的
最后一个有效窗口。原生逐项减法、FP64 插值表和求和顺序保持不变。
`+2` 只作为本实验受限数值域的工程余量，不是任意浮点输入的形式证明。
独立审计另外对五组配置逐点查询实际 native 轨道并检查完整 `d/e` 范围。

原生依据是 [exp16 保留的官方版本 LISAResponse.cu](../../exp16-prepared-detector-response/knowledge/LISAResponse.cu)
中 `interp_single`、`TDI_delay`；轨道窗口来自已安装 `lisatools` 的对应原生实现。
本实验 CPU 门限不覆盖 CUDA 更宽的共享内存预取，所以明确拒绝非 CPU 后端。

## 实测结果与解释

- 10 个回归方法在普通模式和 `python -O` 下均通过。覆盖 1/2/15/25/35/40 阶、
  两代 TDI、三种通道输出、零值/脉冲/随机序列、独立单链顺序、只读与负 stride、
  错误输入、FP64 时间存储以及可恢复 Python 异常。
- 复用 exp16 已认证的六条 master FEW 波形：顺行、逆行各三个初相位；
  36 种接口配置与原版正常入口逐字节相同。输入 B 与旧缓存 A 不同，
  并与独立的 B 参考比较，避免“忽略新参数”也能通过测试。
- [独立审计](../collaboration/linux/audit_final.json) 通过 983 项检查、认证 70 个文件；
  对保存的 180 个数组重算残差，对五组配置检查最小接受缓冲的实际原生下标。

这里的“误差为 0”是上述同后端离散程序的字节一致，不意味着物理模型没有误差。
六条波形只有两组物理内参。真实回放报告里的 `input unchanged` 标签实际验证
“存储的链路与传入值相同”；真正调用前后字节不变的断言在独立单位测试中。
本轮没有新生成 FEW 波形、重新验证 5 GB 表、测量加速比或测试 GPU。
只修改实验副本，没有安装到生产环境。

## 与创新加速的关系，以及不能宣称的事

该修复让上游投影数据可以独立交给下游 TDI，利于继续做固定算子复用、批量输入
和不同方案的公平比较。但接口加了验证与复制成本，不能把它算作又一个加速成果。
下一步应研究准备成本的摊销与实际工作负载，再单独计时。

本轮保留同一时刻求和的链式延迟近似，不把它改成递归延迟。
这是 [原论文式 (19)–(20)](https://arxiv.org/html/2204.06633) 明示的 GW 响应近似；
不能拿它的回归通过当作完整激光噪声消除认证，也不能推断完整物理后验通过。
